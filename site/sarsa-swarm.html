The brief

An implementation of OF-GM-SARSA (Speck and Bucci, ACC 2018): every UAV runs the same small tabular policy from local observations, with one Q-table per behaviour reused for each nearby object.

PythonReinforcement learningPettingZooGymnasiumNumPy

What I built

  1. The simulation engine and environment, built from scratch on PettingZoo and Gymnasium.
  2. Target seeking, cohesion, collision avoidance, alignment and obstacle avoidance modules.
  3. Greatest-mass action selection: modules vote on a heading with weighted Q-values.
  4. A three-phase training schedule with YAML configs, so behaviour changes without code.

How it works

  1. 1

    Observe

    Each UAV looks only at nearby neighbours, obstacles and its waypoint.

  2. 2

    Score

    Five behaviour modules (target, cohesion, collision, alignment, obstacle) each score headings with their own Q-table, applied per object.

  3. 3

    Vote

    Greatest-mass action selection adds the weighted Q-values and picks the best heading.

  4. 4

    Train in phases

    Phase 1 learns target seeking alone, phase 2 flocking and obstacle avoidance, phase 3 everything together.

Engineering decisions

  • Object-focused Q-tables keep the state space tiny however large the swarm grows.
  • Module weights and discounts live in YAML, so behaviour can be reshaped without retraining.
  • The environment follows the PettingZoo API and has a conformance test.
