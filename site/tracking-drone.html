A drone that sees a target, keeps its ID and follows it.

The brief

A modular ROS 2 stack: video comes from a USB camera or Gazebo, a YOLO model trained on VisDrone finds objects, OC-SORT gives each one a stable ID, and a follow-me action server flies the drone through ArduPilot.

C++ROS 2 HumbleONNX RuntimeYOLOOC-SORTOpenCVArduPilotGazebo

What I built

  1. A zero-copy frame pipeline over shared memory (Eclipse iceoryx) to keep latency low.
  2. YOLO detection on ONNX Runtime and OC-SORT multi-object tracking in C++.
  3. Detections time-stamped against their source frame, drawn on the matching cached frame.
  4. A Track action server that holds altitude and distance to the target through ArduPilot DDS.
  5. Full simulation: ArduPilot SITL, Gazebo and an OpenStreetMap world with a moving car.

How it works

  1. 1

    Camera

    A USB camera or the Gazebo camera. The stream manager scales frames to 640×480 and caps them at 30 fps.

  2. 2

    Zero-copy transport

    Frames move between nodes over Fast DDS shared memory, so no node copies an image.

  3. 3

    Detect and track

    YOLO on ONNX Runtime runs at 10 Hz; OC-SORT keeps a stable ID for every object through short occlusions.

  4. 4

    Pick the target

    The operator moves the selection to a neighbouring object with the /change_target service.

  5. 5

    Follow

    The Track action server sends velocity commands to ArduPilot to hold, for example, 25 m altitude at 10 m distance.

Engineering decisions

  • Every stage is its own ROS 2 package, so the detector can run alone, with another model, or on recorded video.
  • Detection runs slower than the camera. Results are time-stamped with a 0.25 s latency budget and drawn on the cached frame they came from (50 frames kept), so boxes never drift.
  • One launch file for simulation and a real camera: mode:=sim or mode:=real.
  • A modified OC-SORT fork, shipped prebuilt, keeps the C++ build simple.
